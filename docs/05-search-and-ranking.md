# 05. 検索設計

実装: `lib/repo.ts`（`searchCompanies` / `searchArticles` / `conditionCounts` / `conditionFilterSql`）、
`app/search/page.tsx`。

構想資料の中核主張——**「製造業の検索軸が、MONOTEの中核になる」**——を、
`conditions` テーブルと企業・記事への多対多リンクで実装したもの。

---

## 5.1 条件タクソノミー

シードで投入される条件は **7カテゴリ 27条件**。

| カテゴリ | 表示名 | 条件 |
|---|---|---|
| `material` | 材質 | ステンレス / 鉄・鋼 / アルミ / 銅・真鍮 / 樹脂 / 繊維・布 |
| `process` | 加工 | 板金・プレス / 切削・機械加工 / 溶接 / 表面処理・熱処理 / 鋳造・鍛造 / 樹脂成形 / 組立 / 検査・測定 / 繊維・染色 |
| `lot` | ロット | 1個から（試作）/ 小ロット（〜100個）/ 〜1,000個 / 量産（1,000個以上） |
| `delivery` | 納期 | 短納期（7日以内） |
| `cert` | 認証 | ISO9001 / ISO14001 / IATF16949 |
| `area` | エリア | 関西 / 関東 / 全国対応 |
| `precision` | 精度 | 高精度±0.01mm |

検索画面での表示順（`CAT_ORDER`）は
`material → process → lot → delivery → cert → area → precision`。

> 構想資料が挙げる8軸のうち「業種・用途」「設備・能力」「課題・目的」はまだ
> 構造化条件になっておらず、`companies.industries` / `equipment` / `capacity` の
> テキストとしてフリーワード検索の対象にとどまる。**次に構造化すべき候補**。

---

## 5.2 絞り込みのセマンティクス

**カテゴリ間は AND、カテゴリ内は OR。**

```
選択: [ステンレス, アルミ] × [板金・プレス] × [短納期]

SQL: 企業が
     (ステンレス OR アルミ を持つ)  AND
     (板金・プレス を持つ)          AND
     (短納期 を持つ)
```

実装（`conditionFilterSql`）は、渡された condition ID をカテゴリごとにグループ化し、
グループごとに `EXISTS (... condition_id IN (...))` を AND で連結する。

これは製造業の選定における自然な読み方
——「材質はSUSでもアルミでもよい、ただし板金ができて、短納期は必須」——に一致する。

---

## 5.3 フリーワード検索

`q` はスペース区切りのトークンを `%` で連結した LIKE パターンにする。

```
"SUS304 薄板"  →  "%SUS304%薄板%"
```

| 対象 | 検索対象カラム |
|---|---|
| 企業 | `name`, `description`, `specialty_process`, `industries`, `equipment` |
| 記事 | `title`, `excerpt`, `tag1`, `tag2` |

条件フィルタと `q` は併用できる（AND）。

## 5.4 ランキング

### 既定（`sort=match`）

```sql
ORDER BY match_count DESC,     -- 選択条件にいくつ合致したか
         verified   DESC,      -- 確認済み企業を上に
         richness   DESC,      -- プロフィールの充実度
         updated_at DESC       -- 新しい情報を上に
```

### `richness` スコア

```
richness = completeness                                     -- 0〜100
         + (写真が1枚以上あるか)              × 40
         + (公開記事の本数)                   ×  6
         + (response_days が設定されているとき) × (5 - response_days) × 8
```

| 要素 | 意図 |
|---|---|
| `completeness` | 対応条件を丁寧に入力した企業を上に |
| 写真 +40 | 現場写真がある企業は判断材料が多い |
| 記事 ×6 | **発信している企業が検索で有利になる** ＝ 投稿インセンティブの中核 |
| 返信速度 | 1営業日なら +32、4営業日なら +8。未設定は0 |

> この設計は、構想資料の「投稿メリットが弱い」というリスクに対する
> **プロダクト側の答え**にあたる。記事を書くほど検索順位が上がり、
> 上がった順位は `impression` としてダッシュボードに返ってくる。

### その他のソート

| `sort` | 挙動 |
|---|---|
| `updated` | `updated_at DESC` のみ |
| `response` | 上記で取得後、`response_days` 昇順に JS 側で並べ替え（未設定は99扱い） |

### 記事の並び
`searchArticles` は `status='published'` に限定し、`published_at DESC`。

## 5.5 ファセット件数（絞り込みサイドバーの数字）

`conditionCounts(filters)` は、
**現在の条件を一度すべて外した企業集合**に対して condition 別の件数を数える。

```
companies = searchCompanies({ ...filters, conditionIds: [] })
→ その集合内で company_conditions を GROUP BY condition_id
```

つまりフリーワードや他の絞り込みは反映しつつ、
「この条件を足したら何社になるか」の目安を出す実装になっている。

---

## 5.6 緩和サジェスト

適用条件に `delivery`（短納期）が含まれるとき、
**それを外した場合の件数**を計算して提示する。

```
ステンレス × 板金・プレス × 1個から × 短納期  →  24社
                            納期条件を外すと  →  48社
```

シードは、この 24 ⇄ 48 がちょうど成立するよう
`targetSUS = 48` / `targetFast = 24` で企業を生成している（→ [07](./07-seed-data.md)）。

> 「条件が厳しすぎて0件」で行き止まりにせず、**次の一手を出す**ための機能。
> 現状は納期条件のみが対象で、他カテゴリへの一般化は未実装。

---

## 5.7 ページングと計測

- 1ページ **10社**（`PER_PAGE`）
- **1ページ目に表示された企業にのみ `impression` を記録**する
  （ページ送りで水増しされないため、ダッシュボードの「検索結果に表示された回数」が意味を持つ）
- `term` は適用条件のラベルを `×` で連結した文字列。条件が無ければ `q` を使う

---

## 5.8 記事 → 企業検索の接続

`/articles/[slug]` は、記事に紐づく `article_conditions` をチップとして表示し、
そのチップから **同じ condition ID で `/search`** へ遷移させる。
あわせて「その条件でヒットする企業数」を `searchCompanies({conditionIds}).length` で表示する。

これが構想資料の
「検索結果は記事だけでなく、企業プロフィール・実績・相談導線へ接続する」の実装にあたる。

---

## 5.9 類似企業

`similarCompanies(companyId, limit)`
自社の条件セットと重なる企業を、**重なり数の降順 → verified 降順**で返す。
企業詳細ページで2社表示する。

`companiesMatchingConditions(conditionIds, limit)` は同じ仕組みを
「記事の条件に合う企業」に使う。

---

## 5.10 順位の逆算（ダッシュボード用）

`lib/extra/admin.ts` の `termRankMap` は、
ダッシュボードの「検索条件別の成果」テーブルに **「今その条件で検索したら何位か」** を出すために、
記録された `term` 文字列を検索条件に逆変換する。

```
term "SUS304 × 小ロット × 短納期"
  → "×" で分割
  → 各トークンを conditions.label に完全一致 → 部分一致 の順でマッチ
  → マッチした条件で searchCompanies() を実行（本番の検索と同じ並び）
  → 自社の位置を "N位 / M社" として返す
  ※ どの条件にも一致しないトークンだけの場合は
     プロフィールテキストへの LIKE 検索にフォールバック
```

**表示のためだけの推定値ではなく、実際の検索関数を通した順位**である点が重要。
