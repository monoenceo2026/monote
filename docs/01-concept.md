# 01. 事業構想

出典: `MONOEN NEW BUSINESS / CONCEPT DRAFT — MONOTE 製造業特化型 情報発信プラットフォーム 初期構想草案 2026.07`
（※資料内の数値は検証用の仮置き）

---

## 1.1 構想の結論

> **専門メディア × 製造業検索 × 発信支援**
>
> MONOTEは、記事数を増やすことではなく、
> 技術情報が **“選定・比較・相談”に使われる状態** をつくる。

### 設計原則（4つ）

| 原則 | 実装上の意味 |
|---|---|
| 登録・投稿の入口は無料 | `/signup` は無料。企業登録・プロフィール・記事投稿・基本検索掲載まで ¥0 |
| 製造業の条件で探せる | `conditions` テーブルを記事・企業の双方に紐づけ、横断検索を成立させる |
| 優先表示・運用支援で収益化 | 投稿そのものではなく「到達・分析・継続運用」に課金する |
| 初期は monoen 編集部が品質をつくる | 記事の `reviewed` フラグ、企業の `verified` 表示、編集記事による供給の先出し |

---

## 1.2 解こうとしている課題

製造業の情報流通には、**三者それぞれに構造的な摩擦**がある。

### 発信する企業
技術はあるが、記事企画・執筆・継続運用の担当者がいない。
公開しても成果が見えにくい。

### 探す企業・技術者
加工法、材質、ロット、精度などの条件で横断検索できず、比較に時間がかかる。

### プラットフォーム（運営）
無料投稿だけでは原価が先行する。
低品質記事が増えると検索体験と信頼性が落ちる。

> **含意**: 「投稿しやすくする」だけでは解けない。
> 摩擦は「探せない」と「成果が見えない」に集中しているため、
> **検索の構造**と**成果の可視化**が同時に必要になる。

---

## 1.3 三者の価値

| | 誰に | 何が変わるか | 具体 |
|---|---|---|---|
| 01 | **投稿企業** | 発信が、営業・採用・信頼形成に使える資産になる | 専門読者への到達／検索に残る技術コンテンツ／反応・相談行動の可視化 |
| 02 | **探す人** | 自社の条件に合う企業・技術・知見へ早くたどり着く | 技術条件から検索／記事と企業情報を一体で確認／保存・比較・相談へ接続 |
| 03 | **monoen** | 編集力と企業ネットワークを、再現性のある事業にする | 編集品質による信頼／検索・閲覧データの蓄積／有料支援への自然な導線 |

---

## 1.4 コアループ：投稿から相談までを一つの循環にする

構想資料のコンセプト図を、実装上のイベントに落とすと次の循環になる。

```
     ┌──────────────────────────────────────────────────────────┐
     │                                                          │
     ▼                                                          │
 ① 企業が発信する                                                │
   ・企業登録（対応条件の構造化）      /signup                    │
   ・技術記事の投稿                    /admin/articles/new       │
     │                                                          │
     ▼                                                          │
 ② 条件で見つかる                                                │
   ・条件検索で候補に出る              /search   → impression    │
   ・記事から同条件の企業検索へ         /articles/[slug]          │
     │                                                          │
     ▼                                                          │
 ③ 検討される                                                    │
   ・企業ページを読む                  /companies/[slug]         │
                                                 → click / view  │
   ・保存する／比較表に入れる           /my/compare  → save       │
     │                                                          │
     ▼                                                          │
 ④ 相談が届く                                                    │
   ・相談・見積依頼を送る              /inquiry/new  → inquiry   │
   ・企業の受信箱に入る                /admin#inbox              │
     │                                                          │
     ▼                                                          │
 ⑤ 成果が返る                                                    │
   ・条件別の表示/クリック/保存/相談を集計  /admin                │
   ・「どの条件で足りないか」が分かる                              │
     │                                                          │
     └──── 次の発信テーマ・プロフィール改善へ ────────────────────┘
```

この循環が回ることが MONOTE の成立条件であり、
`events` テーブル（→ [06. 計測とKPI](./06-measurement.md)）は、この循環の各辺を実際に記録するために存在する。

## 1.5 一般型投稿プラットフォーム（note等）との違い

> noteとの違いは、“投稿機能”ではなく **“選定に使える構造”**。
> 一般型の発信体験を置き換えるのではなく、製造業の**発見・比較・相談**に必要な機能を足す。

| 観点 | 一般型の投稿プラットフォーム | MONOTEの差別化方針 |
|---|---|---|
| 読者 | 幅広いテーマと読者 | 製造業の目的を持つ読者 |
| 発見 | タグ・フォロー中心 | 技術条件・課題からの検索 |
| 運用 | 投稿者が企画・運用を担う | 編集・運用代行を選べる |
| 成果指標 | 閲覧・反応が主 | **保存・比較・相談行動を重視** |

※ 比較は設計方針の説明であり、既存サービスの否定ではない。

---

## 1.6 中核：製造業の検索軸

自由文と一般タグだけでなく、**企業選定に使う条件を、記事・企業プロフィールに構造化して持たせる**。

### 想定する8つの検索軸

| 軸 | 例 |
|---|---|
| 業種・用途 | 自動車 / 半導体 / 医療 |
| 加工・工程 | 切削 / 板金 / 表面処理 |
| 材質 | 鉄 / SUS / 樹脂 / 複合材 |
| 対応条件 | ロット / 精度 / サイズ |
| 設備・能力 | 保有設備 / 生産能力 |
| 認証・品質 | ISO / 検査 / トレーサビリティ |
| 地域・納期 | 対応エリア / 短納期 |
| 課題・目的 | 試作 / 量産 / 改善 / 代替 |

### 目指す検索体験

> 「**SUS304の薄板を、小ロット・短納期で加工できる企業**」

検索結果は記事だけでなく、**企業プロフィール・実績・相談導線へ接続する**。

※ 検索軸の優先順位は業界ヒアリングで検証する前提。
現在の実装は7カテゴリ27条件に絞った検証版（→ [05. 検索設計](./05-search-and-ranking.md)）。

## 1.7 収益モデル

> 無料の裾野を広げ、有料で **“成果までの距離”** を短くする。
> 投稿そのものではなく、**到達・分析・継続運用**の支援に課金する。

| プラン | 位置づけ | 含まれるもの | 価格 |
|---|---|---|---|
| **無料** | 参加と情報蓄積を促す | 企業登録・プロフィール／記事投稿・基本検索掲載／基本的な閲覧反応 | **¥0** |
| **優先表示・レコメンド** | 狙った読者への到達を高める | 検索・特集での優先枠／ターゲット配信・再掲／詳細レポート・改善提案 | 月額 / 施策単位（仮） |
| **運用代行** | 発信を継続できる状態にする | 企画・取材・執筆／投稿・分析・改善／連載・採用・技術PR支援 | 個別見積 |

※ 価格は支払意思・提供原価を確認して設計する（現時点は仮）。

### 実装との接続点

- 無料層は現在の実装でほぼ全て提供されている（登録・投稿・検索掲載・基本レポート）。
- 有料層のうち「詳細レポート」は `/admin` ダッシュボードの条件別成果テーブルが原型。
- 「優先表示」はランキング関数（`searchCompanies` の並び順）に枠を差し込む形で実装可能な構造になっている。

---

## 1.8 リスクと初期対策

> 最大のリスクは **“無料だから伸びる”と考えること**。
> 成長条件と停止条件を先に決める。

| 主要リスク | 初期対策 |
|---|---|
| 無料投稿が原価を圧迫 | 画像容量・投稿上限を設計。高原価機能は有料化し、**企業別の粗利**を追う |
| 投稿メリットが弱い | “閲覧数”ではなく、**専門検索流入・保存・相談行動**をレポートする |
| 品質・信頼性が下がる | 必須項目、編集ガイド、通報・審査、**企業確認済み表示**を段階導入 |
| 記事と読者が集まらない | 連携企業と編集記事で**供給を先につくり**、特定テーマから検索需要を獲得 |

### 停止条件

> **有料意向・検索利用・継続投稿が確認できなければ、対象業種か提供価値を絞り直す。**

### 対策の実装状況

| 対策 | 実装 |
|---|---|
| 専門検索流入・保存・相談のレポート | ✅ `events` + `/admin` ダッシュボード |
| 企業確認済み表示 | ✅ `companies.verified` |
| 編集レビュー | ⚠️ `articles.reviewed` フラグのみ（審査フロー未実装） |
| 必須項目 | ⚠️ 相談フォームのみ必須検証あり。企業プロフィールは充足度（`completeness`）で促す方式 |
| 通報・審査 | ❌ 未実装 |
| 画像容量・投稿上限 | ❌ 未実装（相談の添付は 20件・200文字パスまで、UI上は 20MB 表示） |
