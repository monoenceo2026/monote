# 02. プロダクト仕様（画面別）

MONOTE は「探す側（発注担当）」と「つくる側（掲載企業）」の2つのロールを、
ひとつのサイト上で行き来させる構成になっている。

```
探す側                              つくる側
────────────────────────────       ────────────────────────────
/                TOP                /signup          企業登録
/search          条件検索      ←→   /admin           管理ダッシュボード
/companies/[slug] 企業詳細           /admin#inbox     相談の受信箱
/articles        記事一覧            /admin#company-info 会社情報
/articles/[slug] 記事詳細            /admin/articles/new 記事エディタ
/my/compare      保存・比較
/inquiry/new     相談・見積依頼  ──────────► 受信箱へ
                          /login   デモログイン
```

---

## 2.1 `/` — TOP

| | |
|---|---|
| 実装 | `app/page.tsx`（Server Component, `dynamic = "force-dynamic"`） |
| 目的 | 「つくりたいものから、つくれる会社を探す。」というコンセプトの提示と、検索・記事・企業登録への分岐 |

**構成**
- ヒーロー：モノエンのロゴシンボルを使ったモーフィングモーション（`components/HeroFx.tsx`）
- サイト入場アニメーション：ブランドムービーをオーバーレイ再生（`components/Intro.tsx`）
  - タブセッションにつき1回のみ。`prefers-reduced-motion` ではスキップ
  - 初回描画前にインラインスクリプトが `html[data-intro-off]` を立て、再訪問時のちらつきを防ぐ
- 「やりたいことから選ぶ」カテゴリ（曲げる／削る／流し込む／表面／測る／組み立てる／材料／目的）
- 「読んで探す」：`featuredArticles(4)` — サムネイル付き記事を優先し、足りなければ最新記事で補完
- サイト統計：`siteStats()` = 掲載企業数 / 公開記事数 / 最終更新日
- CTA：`企業を探す` `記事を読む` `特集` `無料で企業登録`

## 2.2 `/search` — 条件検索

| | |
|---|---|
| 実装 | `app/search/page.tsx` + `app/search/parts.tsx` |
| 目的 | MONOTE の中核。製造業の条件で企業・記事を横断的に絞り込む |

**URLパラメータ**

| パラメータ | 意味 | 既定 |
|---|---|---|
| `q` | フリーワード | なし |
| `cond` | 適用する condition ID のカンマ区切り | 未指定かつ `q` なしのときはデモ既定4条件 |
| `sort` | `match`（適合度）/ `updated`（更新順）/ `response`（返信の速さ） | `match` |
| `tab` | `companies` / `articles` | `companies` |
| `page` | ページ番号（1ページ10社） | `1` |

**デモ既定条件**（`q` も `cond` も無いとき）
`ステンレス` × `板金・プレス` × `1個から（試作）` × `短納期（7日以内）`
→ Figmaデザインの「24社」状態を実クエリで再現する。

**主要な要素**

| 要素 | 挙動 |
|---|---|
| 絞り込みサイドバー | カテゴリ別チェックボックス。ラベル横の件数は**他の条件を反映した実件数**（`conditionCounts`） |
| 適用中の条件チップ | 個別に外せる。カテゴリ順（材質→加工→ロット→納期→認証→エリア→精度）に整列 |
| 緩和サジェスト | 納期条件が付いているとき「納期条件を外すと N社」を提示（24社 ⇄ 48社） |
| 企業カード | 適合条件・認証・写真・最新記事1本＋残件数・MONOTE経由の相談数 |
| 比較バー | 最大3社まで。そのまま `/inquiry/new` へ渡せる |
| 記事タブ | 同じ条件で記事を検索（`searchArticles`） |

**副作用**: 1ページ目の表示企業に `impression` イベントを記録する（`term` は適用条件を `×` で連結した文字列、条件が無ければ `q`）。

## 2.3 `/companies/[slug]` — 企業詳細

| | |
|---|---|
| 実装 | `app/companies/[slug]/page.tsx` |
| 目的 | 「この会社に相談してよいか」を判断するために必要な情報を一枚で見せる |

**表示項目**
- 基本：会社名・確認済みバッジ（`verified`）・所在地・従業員数・創業年・説明
- 強み3枠：加工 / ロット・納期 / 品質（`specialty_*` 系カラム）
- 対応条件：加工・材質・ロット・精度・納期・サイズ・エリア・認証
- **対応が難しい条件**（`hard_conditions`）— 断りの明示によりミスマッチ相談を減らす
- 設備・生産能力・取引条件・価格帯の目安・連絡可能時間・返信の目安
- 実績（`works`）、写真（`company_photos`）、その企業の記事（`companyArticles`）
- 似ている企業2社（`similarCompanies` — 条件セットの重なり順）
- MONOTE経由の相談数（`inquiryCountOf`）
- 保存 / 比較に追加 / この会社に相談する

**副作用**（計測の要）
- 常に `view` イベントを記録
- `?from=search` が付いている場合のみ `click` イベントも記録（`term` は `?term`、無ければ `?q`）
- → ダッシュボードの「うち検索経由 N%」はこの差分から算出される

## 2.4 `/articles`, `/articles/[slug]` — 技術記事

| | |
|---|---|
| 実装 | `app/articles/page.tsx`, `app/articles/[slug]/page.tsx` |
| 目的 | 技術記事を「読み物」で終わらせず、**同条件の企業検索へ接続する** |

**一覧** — `latestArticles(24)` と `siteStats()`。

**詳細**
- 本文は `articles.body`（`[{ heading, paragraphs[] }]` の JSON）をセクション描画
- 目次（見出しから自動生成、`#sec-N`）
- 記事に紐づく条件チップ → **同じ条件の `/search` へ直結**、その条件でヒットする企業数も表示
- 執筆企業のプロフィール要約カード（加工・エリア・ロットなど）＋ 相談導線
- 保存ボタン
- 未公開記事（`status !== 'published'`）は 404

**副作用**: `article_view` イベントを記録。保存時は `article_save`。

## 2.5 `/my/compare` — 保存・比較

| | |
|---|---|
| 実装 | `app/my/compare/page.tsx` |
| 目的 | 候補を並べ、優位点を見て、そのまま複数社へ相談する |

**3つのブロック**
1. **比較表**（最大3社）— 行ごとに優位セルをサーバー側で実計算してハイライト

   | 行 | 優位の判定 |
   |---|---|
   | 条件適合 | 適合数が最大（最大値が0のときは誰もハイライトしない） |
   | 対応ロット幅 | `lot_max - lot_min` が最大 |
   | 精度 | `precision_mm` が最小 |
   | 認証数 | 認証条件の数が最大（0件のときはハイライトなし） |
   | 最短納期 | `delivery_min` が最小 |
   | 返信の速さ | `response_days` が最小 |
   | 情報の新しさ | 記事数が最多 **かつ** 更新日が最新 |

   同値が並べば全員がハイライトされる。値が `null`（実績なし）の社は優位にならない。
   各社にメモを付けられる（`compares.memo` に保存）。
2. **保存した企業 / 記事** — `saves` テーブルから
3. **相談履歴** — ログイン中ユーザーが送った `inquiries`

「N社にまとめて相談」で `/inquiry/new?companies=...&source=compare` へ。

## 2.6 `/inquiry/new` — 相談・見積依頼

| | |
|---|---|
| 実装 | `app/inquiry/new/page.tsx`, `InquiryClient.tsx`, `actions.ts` |
| 目的 | 条件が揃った相談を、複数社へ同時に送る |

**3ステップ表示**: `1 相談の種類` → `2 条件を入力` → `3 送信先の確認`

**送信先の決定**
- `?companies=1,2,3` があればその企業
- 無ければ**比較リストの内容**を既定の送信先にする

**入力項目**

| 区分 | 項目 |
|---|---|
| 必須 | 加工・工程 / 材質 / 数量・ロット / 会社名 / 担当者名 / メールアドレス |
| 任意 | 希望納期 / サイズ / 要求精度 / 予算 / 業種 / 備考 / 電話番号 |
| 添付 | PDF / DXF / STEP / 画像（UI表示 20MBまで） |
| 配慮設定 | 匿名で送る（`anonymous`）／他社への転送を希望しない（`no_forward`） |

**アクション**
- `sendInquiryAction` — 必須項目と送信先を検証 → `inquiries` + `inquiry_recipients` を作成 →
  受信企業ごとに `inquiry` と `inquiry_source_<source>` イベントを記録 → `?sent=<id>` の完了画面へ
- `saveDraftAction` — 検証なしで `status='draft'` として保存（受信箱には出ない）

`source` は `search` / `article` / `compare` のいずれか。ダッシュボードの相談ソース内訳になる。

## 2.7 `/signup` — 企業登録（対応条件）

| | |
|---|---|
| 実装 | `app/signup/page.tsx`, `SignupClient.tsx`, `defs.ts`, `actions.ts` |
| 目的 | 「無料で登録し、条件を入れるほど検索に載る」を体験させる |

**入力**
- 会社名
- 加工チップ（レーザー切断／曲げ・ベンダー／TIG溶接／組立／切削・旋盤／プレス／表面処理／熱処理／検査・測定）
- 材質チップ（ステンレス／鉄・鋼／アルミ／銅・真鍮／樹脂／繊維・布／木材／食品材料）
- ロット下限・上限、精度、サイズ、標準納期、特急対応、認証、対応エリア、価格帯、連絡可能時間、対応が難しい条件

**充足度メーター**: `36 + チップ数 × 4`（12〜92% にクランプ）→ `companies.completeness` に保存。
検索ランキングの richness スコアに効く。

**チップ → conditions の変換**（`submitSignupAction`）

| 入力 | 導出される condition |
|---|---|
| 加工/材質チップ | `PROC_CHIPS` / `MAT_CHIPS` のマッピングどおり |
| ロット下限 ≤ 1 | `lot:1個から（試作）` |
| ロット下限 ≤ 100 | `lot:小ロット（〜100個）` |
| ロット上限 > 100 | `lot:〜1,000個` |
| ロット上限 ≥ 5000 | `lot:量産（1,000個以上）` |
| 標準納期の下限 ≤ 7日 | `delivery:短納期（7日以内）` |
| 認証に ISO9001 / ISO14001 | `cert:ISO9001` / `cert:ISO14001` |
| 精度 ≤ 0.01mm | `precision:高精度±0.01mm` |
| エリア選択・都道府県 | `area:全国対応` / `area:関東` / `area:関西` |

**登録後**: 新規なら company ロールのユーザーを作ってログインし、
`次へ` → `/signup?done=1`、`あとで入力して先に進む` → `/admin/articles/new`。
`/search` `/admin` を revalidate するため、**登録した会社は即座に検索でヒットする**。

補助表示として「直近1か月でこの条件はN回検索されている」を `events` の実カウントから出す（`recentSearchCount`）。

## 2.8 `/admin` — 企業管理ダッシュボード

| | |
|---|---|
| 実装 | `app/admin/page.tsx`, `InboxCard.tsx`, `PeriodSelect.tsx`, `DashFx.tsx`, `actions.ts` |
| アクセス | `role === 'company'` かつ `company_id` を持つユーザーのみ。それ以外は `/login` へリダイレクト |
| 目的 | 「発信が成果につながったか」を、閲覧数ではなく**行動**で見せる |

**構成**

1. **KPI 4枚**（直近30日、前30日比）
   - 検索結果に表示された回数（`impression`）
   - 記事・企業ページの閲覧（`click` + `view`）— 補足に「うち検索経由 N%」
   - 保存・比較された数（`save`）
   - 相談・見積依頼（`inquiry`）— 補足に「未対応 N件 / 返信 平均N営業日」
2. **検索条件別の成果テーブル** — 条件（term）ごとの 表示 / クリック / 保存 / 相談 と、
   **「その条件で今検索したら何位か」**（`termRankMap` が実際の検索順序を再計算）
3. **改善サジェスト** — 表示は多い（50回以上）のにクリック率15%未満かつ相談ゼロの条件を提示
4. **よく読まれている記事** — 記事別の閲覧 / 保存 / 相談（30日）
5. **相談のソース内訳** — 検索結果から直接 / 記事を読んでから / 比較表から
6. **会社情報の充足度 TODO** — 価格帯未入力 / 実績5件未満 / 保有設備の型式未記載 を実データで判定
7. **相談の受信箱**（`#inbox`）— `返信する` / `対応できない` で `inquiry_recipients.status` を更新

## 2.9 `/admin/articles/new` — 記事エディタ

| | |
|---|---|
| 実装 | `app/admin/articles/new/page.tsx`, `EditorClient.tsx`, `actions.ts` |
| 目的 | 「書く担当者がいない」企業でも書き出せるように、構造化された入力にする |

- テーマ選択（`case` 事例 / `equipment` 設備 / `quality` 品質 / `people` 人 / `explain` 解説）
- タイトル ＋ セクション（見出し＋本文）の繰り返し
- 記事に紐づける条件（conditions）を選択 → 検索で拾われる
- **自動保存**（`status='draft'`）／社内確認（`review`）／公開（`published'`）を1つのアクションで処理
- 保存時に自動生成されるもの
  - `body` … `[{ heading, paragraphs[] }]` の JSON
  - `tag1` … 選択条件のうち最初の `process` ラベル
  - `tag2` … 最初の `material` ラベル
  - `excerpt` … 最初の段落の先頭80文字（超過時は `…`）
  - `slug` … 新規は `post-<base36 timestamp>`
- 公開時は `/`, `/articles`, `/search`, `/articles/[slug]`, `/companies/[slug]` を revalidate

## 2.10 `/login` — デモログイン

β版デモ環境用のワンクリックログイン（パスワードなし）。

| ロール | ユーザー | 試せること |
|---|---|---|
| 探す側（発注） | 田中 様（`user_id=1`） | 検索、保存・比較（シード済み3社＋メモ）、相談の送信、相談履歴 |
| つくる側（掲載企業） | 株式会社○○製作所（`user_id=2`） | ダッシュボード、相談の受信箱、記事の投稿・公開、対応条件の編集 |

`loginAction` は `userId=2` のとき `/admin`、それ以外は `/` へリダイレクトする。
