# MONOTE

製造業特化型の情報発信・企業検索プラットフォーム。
加工方法・材質・ロット・精度・認証などの条件で、技術記事と企業情報をまとめて検索できます。

Figmaデザイン: https://www.figma.com/design/gnam2ewPe2dZ2ivBazOgBq/MONOTE

## 技術構成

- **Next.js 16**（App Router / TypeScript / Server Components + Server Actions）
- **SQLite**（better-sqlite3）— 初回起動時に `data/monote.db` を自動作成し、デモ用データをシード
  - 掲載企業128社・技術記事342本・検索条件タクソノミー・行動イベント（表示/クリック/保存/相談）
- スタイルはプレーンCSS（`css/`）。デザイントークンは `css/base.css`

## 起動

```bash
npm install
npm run dev    # http://localhost:3000
```

本番ビルド:

```bash
npm run build && npm start
```

DBを作り直す場合は `data/monote.db*` を削除して再起動（自動で再シードされます）。

## デモアカウント（/login からワンクリック）

| ロール | 名前 | 試せること |
|---|---|---|
| 探す側（発注） | 田中 様 | 検索、保存・比較（シード済み3社+メモ）、相談の送信、相談履歴 |
| つくる側（掲載企業） | 株式会社○○製作所 | ダッシュボード（実イベント集計）、相談の受信箱、記事の投稿・公開、対応条件の編集 |

## 主なルート

| ルート | 内容 |
|---|---|
| `/` | TOP。ヒーローはモノエンロゴシンボルのモーフィングモーション |
| `/search` | 条件検索。ファセット件数・緩和サジェスト・比較バーすべて実データ |
| `/companies/[slug]` | 企業詳細。閲覧イベントを記録（ダッシュボードに反映） |
| `/articles` `/articles/[slug]` | 技術記事。条件チップから同条件の企業検索へ接続 |
| `/my/compare` | 保存・比較。優位セルはサーバーで実計算、メモはDB保存 |
| `/inquiry/new` | 相談・見積依頼。送信すると相手企業の受信箱に届く |
| `/signup` | 企業登録（対応条件）。登録した会社は実際に検索でヒット |
| `/admin` | 企業管理ダッシュボード。KPI・検索条件別成果・受信箱（返信/対応不可） |
| `/admin/articles/new` | 記事エディタ。自動保存（下書き）と公開 |

## 環境変数

| 変数 | 必須 | 用途 |
|---|---|---|
| `MONOTE_SESSION_SECRET` | 本番で必須 | セッションCookieのHMAC署名鍵。長いランダム文字列を設定します。未設定のまま本番起動すると起動ごとに鍵が変わり、デプロイやコールドスタートのたびに全ユーザーがログアウトされます |
| `NEXT_PUBLIC_SITE_URL` | 推奨 | 正規URL。OGP・`robots.txt`・`sitemap.xml` の絶対URL生成に使います。未設定時は `https://monote.jp` |

`.env.local`（ローカル）またはホスティングの環境変数に設定してください。

```bash
# 鍵の生成例
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

## ローンチ前の申し送り

以下はデモ・検証用の実装のまま残っている箇所です。実ユーザーを迎える前に対応が必要です。

1. **認証はデモ用**。`/login` はパスワードを検証せず、あらかじめ用意した2つのデモアカウントを
   ワンクリックで切り替えるだけの仕組みです（`app/actions.ts` の `loginAction` は
   デモユーザーID以外を拒否します）。実運用ではメール＋パスワードやOAuthなどの
   本物の認証と、企業アカウントの本人確認フローに差し替えてください。
2. **企業登録は未審査**。`/signup` から登録した企業は `verified = 0` で保存され、
   認証バッジは付きません。掲載前の審査フローは未実装です。
3. **書き込みの永続性**。サーバーレス（Vercel）ではSQLiteが `/tmp` に作られるため、
   保存・比較・相談・記事公開はインスタンスローカルかつ一時的です。上の「デプロイ」を参照してください。
4. **相談メールの送信は未接続**。相談は受信箱（DB）に届きますが、企業への
   メール通知は行っていません。送信基盤の接続が必要です。

## デプロイ

- **Vercel**: そのままデプロイ可能です。サーバーレス環境はファイルシステムが読み取り専用のため、
  SQLiteは自動的に `/tmp` に作成・シードされます（デモ用途）。
  この場合、**書き込み（保存・比較・相談・記事公開など）はインスタンスローカルかつ一時的**で、
  コールドスタートでシード状態に戻ります。複数インスタンスに分かれると書き込みが見えないことがあります。
- **本運用**: 書き込みを永続化するには、永続ディスクのあるホスティング（Render / Railway / Fly.io / VPS 等）で
  `npm run build && npm start` を実行するか、`lib/db.ts` のDB接続を Turso(libSQL) や Postgres に差し替えてください。
  DBアクセスは `lib/repo.ts` に集約してあるため差し替え範囲は限定的です。

## データ・計測の流れ

検索結果の表示は `impression`、検索経由の企業ページ閲覧は `click`、直接閲覧は `view`、
保存・相談もイベントとして記録され、`/admin` のダッシュボードはこれらの30日集計です。
シードデータはFigmaデザインに描かれた数値（検索24社⇄納期を外すと48社、
インプレッション1,284回、受信箱 未対応2件など）が実クエリで再現されるよう調整しています。
